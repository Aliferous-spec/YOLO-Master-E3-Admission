## 4. 如实披露的部分（不是判据，但必须公开）

- 单观测散布仍跨零：三个 seed 的 per-observation std 为 6.6–9.5 个百分点，
  说明 CPU 计时噪声远大于采集链本身的耗时增量。这正是采用区间上界而非点估计的原因。
- 三个 CI 的下界均为正（0.84% / 1.00% / 1.91%），即采集链确实引入了可检测的正向耗时，
  本项目不宣称「零开销」。
- 协议固定为 OFF→ON 单顺序（spec §7 未规定 ABBA 平衡），**残留顺序效应未消除**，
  列为已知限制。若顺序效应存在，其方向是系统性高估或低估 ON 臂，量级未单独标定。
- JSONL 写盘被排除在 ON 臂之外（spec §7 允许）。因此该数字**不代表**开启持久化后的端到端开销。

## 5. 已知限制（结论边界）

- 结论仅适用于：CPU（`device=cpu`）、yolo-master-n @ 640、Windows-10、
  Python 3.11.9 / torch 2.13.0+cpu / ultralytics 8.4.101、workload mot=4/moe=4/latent=1。
- **不外推**到 GPU、分布式、其它数据集或其它模型规模。
- 该数字是**采集链相对前向的耗时增量**，不等于训练减速，也不等于端到端推理延迟增量。
  训练减速的测量另见 `docs/p1-judging-criteria.md`，且不在项目验收范围内。
